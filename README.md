# Мини-синхронизатор заявок

Сервис для синхронизации, нормализации и дедупликации сырых лидов/заявок.

## Логика работы
1. **Получение данных**: забирает исходные заявки из эндпоинта `SOURCE_URL` (`https://test.ooobs.ru/api/orders`).
2. **Нормализация телефонов**:
   - Номера приводятся к формату `+7XXXXXXXXXX` (11 цифр).
   - Поддерживаются форматы `+7...`, `8...`, а также 10-значные номера без кода страны `9XXXXXXXXX` (приводятся к `+79XXXXXXXXX`).
   - Все номера, которые не удаётся привести к 11 цифрам, отбрасываются как невалидные (`invalid_dropped`).
3. **Дедупликация**:
   - При совпадении нормализованного телефона остаётся запись с максимальным `amount`.
   - При равных `amount` выбирается запись с более поздней датой `created_at`.
   - Каждая объединенная дублирующая запись инкрементирует `duplicates_merged`.
4. **Идемпотентность**: повторные запросы к эндпоинту отдают строго детерминированный результат без накопления дублей.

## Формат ответа
```json
{
  "clients": [
    {
      "name": "Иван П.",
      "phone": "+79991234567",
      "email": "",
      "amount": 5000
    }
  ],
  "stats": {
    "received": 17,
    "unique": 8,
    "duplicates_merged": 5,
    "invalid_dropped": 4
  }
}
```

## Хранение секретов и архитектурное решение
- **Хранение секретов**: Конфигурация и переменные окружения (`PORT`, `SOURCE_URL`, API-ключи) хранятся в переменных окружения (`process.env`) / файле `.env`, который добавлен в `.gitignore` и не попадает в публичный репозиторий. На платформах развёртывания (Vercel, Render) переменные задаются через панель Environment Variables.
- **Почему Node.js**: Для микросервиса потоковой синхронизации и трансформации JSON Node.js идеален — нативный `http` и встроенный `fetch` обеспечивают 0 внешних зависимостей, мгновенный холодный старт (<10мс), низкое потребление RAM и возможность развертывания на любом сервере/serverless платформе без сборки.

## Запуск локально
```bash
node server.js
```
или
```bash
npm start
```
Сервер запустится на `http://localhost:3000`.
